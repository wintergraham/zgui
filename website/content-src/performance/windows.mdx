## Variable-height list

<WinScene scene="vlist">

> **Why zgx's fling shows long frames here.** zgx scrolls in whole device pixels, as Chrome and Windows' own lists do, so text stays crisp. The fling ends slowly: its last ticks move the list less than a pixel each (160 px a tick, decaying to 0.6), so on some refreshes nothing moves on screen, and the capture counts those as long frames. zgx still presented on every refresh, its GPU work done within 0.2 ms of each present; scrolling a steady 12 or 3 px a tick, it shows none. Rune draws at fractional positions, so its pixels change on every tick.
